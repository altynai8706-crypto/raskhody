# Бюджет по категориям

## Для кого и зачем

Для семьи из четырёх человек: планировать расходы на текущий месяц, видеть остаток по каждой категории и вовремя замечать перерасход.

## Что должно быть

- Раздел «Бюджет на месяц» с названием текущего месяца и года по местному времени устройства.
- Пять существующих категорий: «Еда», «Транспорт», «Дом», «Личные расходы», «Другое». Для каждой — поле «Лимит», суммы «Потрачено» и «Осталось».
- Лимиты задаются отдельно для каждого календарного месяца. В новом месяце лимиты пустые; автоматически из прошлого месяца не переносятся. Сохранённые лимиты прежних месяцев остаются в хранилище. Выбор другого месяца в эту функцию не входит.
- Лимит — сумма в тенге от нуля, до двух знаков после запятой; допускаются запятая и точка. Пустое поле означает «Лимит не задан», а `0` — установленный нулевой лимит. Очистка поля и сохранение убирают лимит этой категории.
- Одна кнопка «Сохранить лимиты» сохраняет все пять полей текущего месяца. Ошибка хотя бы в одном поле отменяет всё сохранение, показывает понятное сообщение и сохраняет введённые значения для исправления.
- «Потрачено» — сумма всех расходов категории за весь текущий календарный месяц, включая внесённые будущие даты этого месяца. Фильтры истории не влияют на бюджет.
- «Осталось» = лимит − потрачено. Если лимит не задан, вместо остатка показано «Лимит не задан», расходы всё равно видны.
- При расходах выше лимита показаны отрицательный остаток и текст «Перерасход на …». Предупреждение заметно не только по цвету. При точном достижении лимита остаток равен нулю, предупреждения о перерасходе нет. Расходы не блокируются.
- Общий блок месяца: «Бюджет» — сумма заданных лимитов, «Потрачено» — все расходы месяца, «Осталось» — разница этих сумм. Если заданы не все лимиты, показана подпись «Лимиты заданы не для всех категорий»; общий остаток учитывает расходы и категорий без лимита. Если лимитов нет совсем, вместо бюджета и остатка показано «Бюджет не задан», общие расходы видны.
- Для заданного общего бюджета при отрицательном общем остатке показано «Перерасход на …» независимо от предупреждений отдельных категорий.
- После успешного сохранения лимитов, добавления, изменения или удаления расхода суммы и предупреждения обновляются сразу. Несохранённый ввод лимитов не меняет расчёты до сохранения.
- При наступлении нового месяца раздел обновляется автоматически, в фоновой вкладке — при возвращении. Несохранённые поля прошлого месяца не записываются в новый месяц.
- Лимиты сохраняются в localStorage и восстанавливаются после F5. Существующие расходы сохраняются. При ошибке записи изменения лимитов не применяются, поля остаются для повторной попытки. Если сохранённые бюджеты невозможно прочитать, их перезапись блокируется с понятным сообщением.

## Примеры

Примеры рассчитаны на месяц без других расходов. Для проверки использовать отдельный профиль браузера или учитывать имеющиеся суммы; личные данные не удалять.

- Лимит «Еда» `10000`, «Транспорт» `2000`, остальные пустые. Расходы: еда `2500`, транспорт `500`. Остатки: еда `7 500 ₸`, транспорт `1 500 ₸`. Общий бюджет `12 000 ₸`, потрачено `3 000 ₸`, осталось `9 000 ₸`; видна подпись о неполных лимитах.
- Добавить «Дом» `1000` без лимита: у дома потрачено `1 000 ₸`, остаток не задан. Общие расходы `4 000 ₸`, общий остаток `8 000 ₸`.
- При лимите еды `10000` и расходах еды `10500`: остаток `−500 ₸`, предупреждение «Перерасход на 500 ₸». Снизить расход до `10000`: остаток `0 ₸`, предупреждение исчезает.
- Нулевой лимит транспорта и расход `500`: остаток `−500 ₸`, предупреждение о перерасходе. Очистить лимит и сохранить: вместо остатка «Лимит не задан», предупреждение категории исчезает.
- Все пять лимитов по `1000`, единственный расход — еда `5500`: общий бюджет `5 000 ₸`, потрачено `5 500 ₸`, остаток `−500 ₸`, общее предупреждение о перерасходе на `500 ₸`.
- Ввод `12,50` или `12.50` сохраняется как `12,50 ₸`. Значения `-1`, `1,234`, буквы и суммы за пределами точного расчёта не сохраняются.
- Расход прошлого месяца не меняет текущий бюджет. После F5 лимиты и расходы на месте. В новом месяце лимиты не заданы, расходы считаются только за новый месяц.

## Ограничения

- Только HTML, CSS и JavaScript без npm, библиотек, внешних ресурсов и сетевых запросов. Запуск двойным щелчком по index.html.
- Данные только в localStorage текущего браузера, без синхронизации и отдельных бюджетов членов семьи.
- Русские короткие подписи, поля и кнопки не меньше 44 px; на ширине 375 px нет горизонтальной прокрутки, все действия доступны с клавиатуры.
- Расчёты в целых сотых тенге с проверкой точности отдельных сумм и итогов, формат денег соответствует существующему приложению.
- Без новых категорий, выбора месяца, переноса остатков, доходов и уведомлений вне страницы.
- Существующие добавление, изменение, удаление, сортировка и фильтры расходов продолжают работать.
- Код — только после команды «делай», по одному шагу за раз. Новые файлы тестов не создавать. README.md обновить после последнего шага.

## Готово, когда

- Все пять категорий позволяют сохранить, изменить и убрать лимит; ноль отличается от отсутствия лимита.
- Ошибочный ввод не сохраняет ни одно из полей; введённое остаётся доступным для исправления.
- Примеры выше дают указанные суммы; изменение суммы, категории или даты расхода и удаление сразу пересчитывают бюджет.
- Расходы вне текущего месяца и фильтры истории не искажают расчёты; внесённые будущие даты текущего месяца учитываются.
- Перерасход категории и общего бюджета показан текстом и цветом; при равенстве лимиту предупреждения нет.
- Без лимитов и с частичными лимитами нет вводящих в заблуждение остатков, показаны предусмотренные подписи.
- F5 сохраняет лимиты и прежние расходы. Ошибки чтения и записи бюджетов видны, прежние данные не перезаписываются при ошибке чтения.
- Проверена смена месяца, включая декабрь → январь: старые лимиты сохранены, новые пустые, несохранённый ввод не переносится.
- На ширине 375 px все суммы, подписи и действия доступны; поля и кнопки не меньше 44 px.
- Страница работает при локальном открытии без сети; прежние функции проходят проверку из README.md. README.md дополнен описанием бюджета и примерами ручной проверки после последнего шага.

## Шаги

Для ручной проверки откройте index.html двойным щелчком в отдельном профиле браузера без расходов. Проходите шаги по порядку после их реализации; данные между проверками не очищайте. Каждый список ниже рассчитан на пару минут.

- [x] 1. Ввод и сохранение лимитов текущего месяца.
  На экране: раздел с месяцем, пятью полями лимитов, кнопкой сохранения и сообщениями об ошибках.
  Проверка:
  1. Сохраните лимиты: еда `10000`, транспорт `0`, остальные пустые.
  2. Нажмите F5 — значения остались.
  3. Сохраните еде `-1` — появится ошибка, значение не сохранится.

- [x] 2. Расходы и остатки по категориям.
  На экране: у каждой категории суммы «Потрачено», «Осталось» или подпись об отсутствии лимита.
  Проверка:
  1. Нажмите F5 и добавьте еду `2500` за сегодня — потрачено `2500`, осталось `7500`.
  2. Измените эту трату на `3000` — потрачено `3000`, осталось `7000`.

- [x] 3. Предупреждения о перерасходе категорий.
  На экране: отрицательные остатки и текст предупреждения для категорий с превышенным лимитом.
  Проверка:
  1. Измените ту же трату на `10500` — остаток `−500 ₸`, видно «Перерасход на 500 ₸».
  2. Измените её на `10000` — остаток `0 ₸`, предупреждение исчезло.

- [ ] 4. Общий бюджет месяца и итоговая проверка.
  На экране: общий бюджет, расходы, остаток, подпись при неполных лимитах и общее предупреждение о перерасходе. Проверяются смена месяца, ошибки хранения, мобильный вид и прежние функции по разделу «Готово, когда»; обновляется README.md.
  Проверка:
  1. Сохраните все пять лимитов по `1000` — общий бюджет `5000`, потрачено `10000`, остаток `−5000`, видно предупреждение.
  2. Нажмите F5 — лимиты и общие суммы остались.
  3. Сузьте окно до ширины телефона — все поля и кнопки доступны без горизонтальной прокрутки.
